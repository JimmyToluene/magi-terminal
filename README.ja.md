## これは何か

2つのターミナルパレットと、フォントのビルドツール。

すべての色値は画面上に実在したもの、または4つの公式カラーのいずれかに遡ることができ、すべてのスロットは黒地に対するコントラスト比を実測して決めています。フォントは、NERVのディスプレイが下敷きにした実物のNEC PC-9801 ROM書体を、自由に使えるクリーンルーム素材だけから構築したものです。著作物であるファームウェアは一切使いません。

パレットはエスケープシーケンスによって、SSHで**接続した先の**マシンから送出されます。したがって見た目はワークステーション側についてまわり、どのクライアントから繋いでも同じになります。

## 2つのパレット

### MAGI モノクローム（デフォルト）

MAGIの、黒地にアンバーの文字画面そのもの。16個のANSIスロットすべてが、2つの公式カラー（NERVオレンジ `#F66E25` とEVAイエロー `#F6E201`）の間を補間した単一のランプ上の点です。どのスロットもそのランプ上に乗ります。

![MAGIモノクロームのパレット](images/palette-magi.png)

### NERV コンソール

アンバーが画面を支配する点は変わりませんが、『エヴァ』が色に意味を与えている箇所だけ色相を残しています。`git diff` や `pytest` の出力を一日中読むなら、こちらを。赤と緑は開発作業でもっとも情報量を担う組み合わせであり、モノクロームはそれを潰してしまいます。

![NERVコンソールのパレット](images/palette-nerv.png)

## インストール

```bash
git clone https://github.com/JimmyToluene/magi-terminal.git ~/magi-terminal
cp ~/magi-terminal/magi.sh ~/.config/magi.sh
```

続いて、**SSHで接続する先のマシン**の `~/.zshrc`（または `~/.bashrc`）に以下を追記します：

```bash
if [[ -o interactive && -t 1 && $TERM != dumb && $TERM != linux ]]; then
  source ~/.config/magi.sh
fi
```

このガード条件は重要です。`-t 1` の判定を省くと、エスケープシーケンスが非TTYのストリームへ流れ込み、`scp`・`rsync`・SSH経由の `git` を壊します。

**Powerlevel10k を使っている場合は、このブロックを p10k の instant prompt ブロックより前、つまりファイルの最初に置いてください。** instant prompt は `.zshrc` がコンソールへ書き出す出力をすべて捕捉するため、それより後で発行されたエスケープシーケンスは端末に届きません。この失敗は無言で、しかも誤診しやすい挙動になります。ログイン時にはパレットがまったく効かないのに、直後に手動で `magi.sh` を source すると正常に効くため、クライアント側の問題に見えてしまうのです。呼び出しをバックグラウンドへ回しても解決しません。サブシェルは同じ捕捉済みの stdout を引き継ぐからです。

```bash
source ~/.config/magi.sh                # MAGI モノクローム（デフォルト）
EVA_ACCENT=1 source ~/.config/magi.sh   # NERV コンソール
```

ターミナル自体のテーマエディタに手で色値を入力しても構いません。[サーバー側で制御できるもの・できないもの](#サーバー側で制御できるものできないもの)を参照してください。

## 配色の根拠

NERVの画面に公式のカラースペックは存在しません。あれはセルと初期のデジタル作画であり、そもそもブランドシステムを持たずに作られたものだからです。しかし**典拠として確かなもの**が3つあり、本プロジェクトはそのすべてをそこから組み立てています：

- **4つの公式カラー**。1995年から変わっていません。オレンジ `#F66E25`、イエロー `#F6E201`、ブラック、ホワイト。
- **ガイアノーツの公式ライセンス版EVAカラーシリーズ**（EV-01 エヴァパープル、EV-02 エヴァグリーン、EV-06 エヴァレッド、EV-11 エヴァ試作機イエロー）。どの色がどの機体のものかを確定させてくれます。
- **設定上の色の意味論**。これが最も重要です：**パターン青は対象が使徒であると確定したことを、パターン橙はMAGIが分類しかねていることを意味します。** NERVの画面の地は黒で、その上に緑の六角格子が反復します。

この最後の点が設計全体を決めました。『エヴァ』において画面の色は**情報**を担います。だからNERVコンソールでは、各スロットの色相にそれぞれ由来があります：

| スロット | 色値 | 画面上の出典 |
|---|---|---|
| 背景 | `#000000` | タイトルカードの黒。つねに純黒 |
| 前景 | `#FF9900` | NERVコンソールの本文テキスト |
| カーソル | `#F66E25` | NERVロゴの公式オレンジ |
| 赤 | `#E81900` | 警告の赤／弐号機 |
| 緑 | `#41BB42` | 初号機のストライプ／画面の六角格子 |
| 黄 | `#F6E201` | 公式EVAイエロー／零号機（試作型） |
| 青 | `#54A2D4` | **パターン青**：使徒確定 |
| マゼンタ | `#9B78C4` | 初号機の装甲パープル |
| 明るい白 | `#FFFFFF` | マティスEBのタイトルカードの白。全体で唯一の純白 |

背景は `#000000` に固定し、灰色方向へ柔らげることはしません。タイトルカードもMAGIの画面も純黒であり、そこを妥協した瞬間に全体が崩れます。

## 画面の再構築

以下の画面はすべてゼロから描き起こしたものです。`tools/make-nerv-screens.py` は、上記のパレットと本リポジトリが生成する PC-9800 フォントだけを用い、640×400 のキャンバス（それらの画面が範を取った PC-9801 の実解像度）に描画します。したがってこれらは完全な自作素材であり、同時にパレットの実動デモにもなっています。

```bash
python3 tools/make-nerv-screens.py -o images/
```

**MAGI の決議画面。** 3系統、3つの独立した判断。そして唯一の否決は、警告レッドだけがそれを示します。折れるのは CASPER。赤木ナオコの「女として」の側面を受け持つユニットであり、MAGI の膠着が物語を動かしうる理由です。

![MAGIの決議画面](images/nerv-magi.png)

**パターン青。** シリーズにおける色の使い方として最も重い一例です。青は、目標の波形が使徒のそれと一致したことを意味します。この一画面が NERV コンソール配色の存在理由そのものです。青が青であるあいだだけ、この読み出しは情報として成立します。

![パターン青の読み出し](images/nerv-pattern-blue.png)

**緊急事態。** 公式EVAイエローの警戒縞をタイトルカードの黒に重ね、宣言そのものは警告レッドで示します。

![緊急事態宣言](images/nerv-alert.png)

## 可読性

明度は**ターミナルにおける役割**に従って割り当てています。作業画面でよく読まれるスロットほど明るくなります。

これをわざわざ書くのは、逆をやると「美しいが読めない」パレットができあがるからです。青は『エヴァ』では稀な色なので、スロット4は暗くすべきだという理屈は成り立ちます。しかしスロット4は `ls` がディレクトリに使う色（`DIR=01;34`）であり、作業画面でもっとも読まれる色付きテキストです。本パレットの初期版は、スロット4を黒地に対して **2.8:1** に置いていました。使い物になりません。

現在はすべてのスロットを実測しています。MAGIモノクロームで後退を許しているのは「黒」と「明るい黒」だけです：

| | `#000000` に対するコントラスト比 |
|---|---|
| ディレクトリ（スロット4） | **8.9:1** |
| 後退色を除く最低値 | 5.9:1 |
| 最高値 | 19:1 |
| 明るい黒（UIの罫線、コメント） | 4.0:1、意図的に低く |

WCAGの相対輝度の式でどんなパレットでも自分で検証できます。背景に対して4.5:1を下回るものは、意識的な選択であるべきです。

## PC-9800 フォント

第七話の `Jet Alone` 起動画面は、**NEC PC-9800シリーズ**を下敷きにしています。当時の日本を席巻していたPCプラットフォームです。冒頭の数行は実機PC-9801のBIOSメモリチェックと一致し、`addr PSP blks size` の表は `VMAP.COM` という、かなりマイナーな国産メモリ診断ツールの出力です。字形はPC-9801のROMに焼かれた8×16のANKビットマップフォント。その角ばったセリフこそが、この画面が「西洋のDOS窓」に見えない理由です。IBMのVGA CP437フォントは実質サンセリフですから。

[`hikaen2/ttf-pc9800`](https://github.com/hikaen2/ttf-pc9800) は、PC-9801の `FONT.ROM` ダンプをTrueTypeへ変換します。**ただし同リポジトリに同梱されている `FONT.ROM` はプレースホルダです**。288,768バイト、中身は `0xFF` のみ。サイズだけは正確なので `make` は最後まで通り、そして全グリフが塗り潰された四角のフォントができあがります。

`tools/freecg98-to-fontrom.py` は、NECのファームウェアそのものを不要にします。DOSBox-Xに同梱される自由なクリーンルーム実装のAnex86互換PC-98フォント `FREECG98.BMP` を読み込み、ttf-pc9800のパーサが期待するバイト配置で `FONT.ROM` を書き出します：

```bash
sudo apt install -y git make ruby fontforge-nox potrace bdfresize
git clone https://github.com/hikaen2/ttf-pc9800.git && cd ttf-pc9800
curl -sLO https://github.com/joncampbell123/dosbox-x/raw/master/contrib/fonts/FREECG98.BMP
python3 ../tools/freecg98-to-fontrom.py FREECG98.BMP -o data/FONT.ROM
make
```

成果物は `dist/` に `pc-9800-regular.ttf` と `pc-9800-bold.ttf` として出力されます。

ビルドしたフォントで再現したJet Alone起動画面、32pxと16px：

![32pxの起動画面](images/boot-32px.png)

![16pxの起動画面](images/boot-16px.png)

注意点が2つ：

- **出力に `post.isFixedPitch = 1` を立ててください。** ラテン字のアドバンス幅はすべて512で統一されており、PANOSEも等幅を宣言していますが、FontForgeはこのフラグを立てません。そして多くのアプリケーションが「等幅フォント」を絞り込む際に見ているのは、まさにこのフラグです。立てないと、フォント一覧に現れないことがあります。
- `FREECG98.BMP` はNECのROMの**再現版**です。PC-98らしさと正しい8×16のメトリクスは備えており、字形は原典に近いところまで寄せてあります。厳密さが必要なら、実機からのダンプを置いて `make` し直してください。

このフォントは16pxの字身の整数倍でもっともシャープに出ます。ぼやけて見えるときは、まず16と32を試してから1段ずつの調整に移ってください。

## サーバー側で制御できるもの・できないもの

ターミナルの見た目は2台のマシンのあいだで折衝された結果であり、クライアントごとに対応範囲が大きく異なります。実際には3層に分かれます：

| | ANSIカラー（`OSC 4`） | 背景（`OSC 11`） | フォント |
|---|---|---|---|
| xterm、kitty、Alacritty、iTerm2、GNOME Terminal、Windows Terminal | 自動 | 自動 | クライアント側 |
| Termius | 自動 | 手動：テーマエディタで設定、デバイス間で同期 | クライアント側 |
| MobaXterm（PuTTY系） | 非対応 | 非対応 | クライアント側 |

**フォントは常にクライアント側です。** サーバーが送るのはバイト列であり、グリフを描画するのはクライアントです。どんなエスケープシーケンスもこれを変えられないため、TTFは使うデバイスすべてに個別にインストールしてください。

`OSC 4` を完全に無視するクライアントでは、色値をそのクライアント自身のカラー設定に入力してください。どの層に属するかは次のコマンドで確認できます：

```bash
printf '\033]4;1;#00FF00\007'; printf '\033[31mこの行が緑ならOSC 4が効いています\033[0m\n'
```
